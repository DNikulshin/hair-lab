Задача: ${@:-<номер issue и что сделать>}

Сначала прочитай `AGENTS.md` (там команды, границы слоёв, правила ПДн и git-процесс),
затем `docs/workflow.md`. Дальше выполняй цикл по этапам — каждый этап отдельный субагент
из `.pi/agents/` (проектные агенты перекрывают глобальных).

Подготовка:
- номер issue возьми из задачи, при отсутствии — создай issue через `gh issue create`
  с метками `type:*`, `area:*`, `prio:*` и статусом `status:in-progress`;
- ветка от `main`: `feat|fix|chore|data|design/<номер>-<коротко>`;
- каталог артефактов: `.pi/artifacts/<YYYY-MM-DD>-<номер>-<slug>/`.

Этапы:
1. `plan` (read-only) — изучи код и требования, верни пошаговый план по формату агента.
   Сохрани в `<артефакты>/plan.md`.
2. `code` — передай план, номер issue и требования AGENTS.md. Он правит файлы и прогоняет
   проверки. После этапа сам запиши `<артефакты>/code-report.md`: изменённые файлы,
   что именно изменено, вывод проверок (кратко), «не проверено» с причиной.
3. `review` (read-only) — передай план и дифф (`git diff main...HEAD`). Сохрани ответ
   в `<артефакты>/review.md`.
4. Если `review` вернул BLOCKER/MAJOR внутри скоупа плана — один повтор `code` + `review`.
   Максимум 2 итерации, дальше остановись и покажи итог. Замечания вне скоупа — в
   `<артефакты>/followups.md`, итерацию не запускают.
5. Коммиты и push делаешь ты (не субагенты): атомарные коммиты по формату
   `<type>(<scope>): <что>`, затем `git push -u origin <ветка>` и
   `gh pr create --fill` с телом по шаблону и строкой `Closes #<issue>`.
   PR **не мержить** — merge делает владелец.
6. Поставь метку `status:review` (workflow `board.yml` сделает это сам, проверь).

Правила:
- правки файлов — только субагент `code`; ты коммитишь, пушишь и ведёшь артефакты;
- проверки строго в порядке: `contracts build` → `typecheck` → `lint` + `check:arch` → тесты;
- не расширяй скоуп, не трогай `.env*`, `node_modules`, lockfile без причины;
- контракты только обратно совместимые, БД — только миграциями expand/contract.

Итог в ответе: ссылка на PR, ветка, список изменённых файлов, число итераций,
результаты проверок, follow-ups.
