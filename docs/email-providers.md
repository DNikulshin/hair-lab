# Почта: варианты реализации для продакшена

## Решение (принято)

**Свой ящик на домене салона у российского почтового провайдера, отправка по SMTP.**

- Исходные условия от владельца: платных Google Workspace / Яндекс 360 нет, домен ещё не выбран,
  DNS под контролем владельца, трансграничная передача персональных данных не допускается.
- Провайдер ящика: **Яндекс 360 для бизнеса** (рекомендуемый, от 279 ₽/мес за сотрудника) или
  **VK WorkMail** (от 309 ₽/мес). Меняется одна переменная `SMTP_HOST`, код не затрагивается.
- Канал: только SMTP с ящика `no-reply@<домен>`. HTTP API и вебхуки провайдера не используем.
- Что это означает для реализации:
  - **вебхуков о доставке нет** — статус письма определяем по SMTP-ответу: 5xx → постоянная
    ошибка (адрес в suppression list), 4xx/таймаут → ретрай с backoff;
  - трекинг открытий и кликов не делаем (и не нужно);
  - лимиты провайдера на отправку с ящика контролируем сами: не больше ~30 писем в минуту
    и ~200 в сутки, этого хватает на 10 записей в день;
  - обязательны SPF, DKIM, DMARC на домене — иначе письма о записи попадут в спам;
  - отправитель — отдельный ящик `no-reply@`, ответы клиентов уходят на `hello@`.
- Условия пересмотра решения (переход на API-провайдера, Unisender/Mailopost):
  объём больше 300 писем в сутки, жалобы на доставляемость, блокировка ящика за «массовую
  рассылку» или потребность в статусах доставки. Адаптер `EmailTransport` это допускает.

Ниже — разбор, на котором решение основано.

Черновик решения к issue #26. Пока провайдер не выбран, в конфигурации действуют дефолты
`smtp.gmail.com:465` (issue #23), а код пишется через адаптер, чтобы смена провайдера
не затрагивала бизнес-логику.

## Что и сколько отправляем

Только **транзакционные** письма (маркетинговых рассылок в MVP нет):

| Письмо               | Когда                       | Данные внутри                         |
| -------------------- | --------------------------- | ------------------------------------- |
| Ссылка для входа     | запрос клиента              | одноразовая ссылка                    |
| Подтверждение записи | после оплаты                | имя, услуга, дата/время, адрес салона |
| Отмена/перенос       | действие клиента или салона | те же + причина                       |
| Напоминание о визите | за 24 ч (позже)             | услуга, время                         |

Объём: 10 записей в день × 2–3 письма ≈ **500–1000 писем в месяц**, пик — до 100 в сутки.
Чеки 54-ФЗ отправляет **ЮKassa**, если передать `PAYMENT_RECEIPT_EMAIL` — это не наша нагрузка.

## Критерии выбора

1. **Доставляемость** — домен салона, SPF/DKIM/DMARC, репутация IP.
2. **Вебхуки о доставке** (`delivered`, `bounced`, `complained`, `opened`) — нужны для outbox:
   ретраи, подавление адресов, статусы. У обычного почтового ящика их нет.
3. **152-ФЗ** — email + имя клиента это персональные данные. Передача за границу требует
   уведомления РКН и оценки рисков; для салона проще держать данные в РФ.
4. **Оплата из РФ** — у зарубежных сервисов карта часто не проходит, аккаунт могут заблокировать.
5. **Канал интеграции** — SMTP достаточно, HTTP API удобнее (идемпотентность, шаблоны, статистика).
6. **Стоимость и предсказуемость** — фиксированный тариф важнее копеечной цены за письмо.
7. **Сложность поддержки** — один человек в проекте, значит внешний сервис лучше своего сервера.

## Варианты

### A. Google Workspace (SMTP, текущий дефолт)

Плюсы: ящик на домене, ничего не нужно подключать, знакомый интерфейс.
Минусы: это почтовый сервис, а не транзакционный — **нет вебхуков о доставке и баунсах**,
жёсткие лимиты на отправку с ящика, репутация домена целиком на нас, оплата и доступность
из РФ нестабильны, данные у зарубежного оператора (152-ФЗ).

Вывод: годится для переписки с клиентами и тестов, не как основной канал записи.

### B. Яндекс 360 (SMTP)

Плюсы: российский, домен и ящики на нём, стабильно работает в РФ, ПДн в РФ, оплата рублями.
Минусы: как и Google — почтовый сервис: нет вебхуков, лимиты на отправку, транзакционная
доставляемость хуже специализированного провайдера.
Ориентир по цене: тарифы для бизнеса от нескольких сотен рублей за ящик в месяц (проверить
актуальные на дату решения).

### C. Российские транзакционные провайдеры: Unisender, Mailopost, DashaMail, Sendsay

Плюсы: API + SMTP, вебхуки о доставке и баунсах, suppression list, шаблоны, статистика,
серверы в РФ (проще с 152-ФЗ), оплата рублями, поддержка на русском.
Минусы: отдельный договор и настройка домена (DKIM), у части сервисов UI перегружен
маркетинговыми функциями.
Ориентир по цене (Unisender, на дату проверки): Фри — 0 ₽ и 1500 писем/мес,
Лайт — 672 ₽/мес, Стандарт — 952 ₽/мес. Тарифы перепроверить перед выбором.

### D. Зарубежные транзакционные: Resend, Postmark, Mailgun, Brevo, Amazon SES

Плюсы: лучший DX и доставляемость, полноценные вебхуки, шаблоны, подробная аналитика.
Ориентир: SES — около 0,10–0,16 $ за 1000 писем; Resend/Postmark — от ~15–20 $/мес за 10 000 писем.
Минусы для этого проекта: трансграничная передача ПДн (152-ФЗ), оплата из РФ, риск блокировки
аккаунта — то есть риск, что клиент не получит письмо о записи.

### E. Свой SMTP (Postfix/mailcow в контейнере)

Плюсы: полный контроль, «бесплатно».
Минусы: репутация IP, PTR-запись, борьба со спам-фильтрами, мониторинг очереди, простой
сервера = потеря писем. Для одного разработчика — неоправданно.

## Сравнение

| Вариант                           | Канал      | Вебхуки о доставке | ПДн в РФ | Оплата из РФ | Цена при нашем объёме | Итог                                    |
| --------------------------------- | ---------- | ------------------ | -------- | ------------ | --------------------- | --------------------------------------- |
| Google Workspace                  | SMTP       | нет                | нет      | рискованно   | ~$7/ящик              | не для транзакций                       |
| Яндекс 360                        | SMTP       | нет                | да       | да           | низкая                | приемлемо на старт                      |
| Unisender / Mailopost / DashaMail | API + SMTP | да                 | да       | да           | 0–700 ₽/мес           | **рекомендую**                          |
| Resend / Postmark / SES           | API + SMTP | да                 | нет      | нет          | ~$0–20/мес            | только при отказе от 152-ФЗ-ограничений |
| Свой SMTP                         | SMTP       | нет                | да       | —            | цена поддержки        | нет                                     |

## Рекомендация (до решения владельца)

Для сравнения: лучшая транзакционная доставляемость была бы у специализированного провайдера
с API и вебхуками. Она отклонена по условиям владельца: нужен свой ящик и только Российская
Федерация. Итоговое решение — в начале документа.

## Как это ложится в код

```
apps/api/src/shared/email/
  transport.ts        интерфейс: send(message) → providerMessageId
  smtp.transport.ts   nodemailer (любой SMTP: Яндекс, Google, Unisender)
  api.transport.ts    HTTP API провайдера (Unisender/Resend) — когда выбран
  index.ts            выбор по EMAIL_PROVIDER, публичный API модуля
```

- Отправка только через **outbox + воркер**: создание записи не зависит от почты.
- Идемпотентность: `messageId` в outbox, повторная отправка не дублирует письмо.
- Вебхуки провайдера обновляют статус письма и suppression list.
- В логах — только id письма и статус; адрес и текст не логируются.
- Конфигурация: `EMAIL_PROVIDER` (`smtp` | `unisender` | ...), `EMAIL_FROM`, `EMAIL_FROM_NAME`,
  остальное — по выбранному провайдеру. Текущие `SMTP_*` остаются рабочими.

## Что осталось сделать владельцу

1. Выбрать домен и провайдера ящика (Яндекс 360 или VK WorkMail).
2. Завести ящики: `no-reply@<домен>` (отправка) и `hello@<домен>` (ответы клиентов).
3. Добавить DNS-записи: MX, SPF, DKIM (значения выдаёт провайдер), DMARC — минимум `p=none`
   на старте, затем `p=quarantine`.
4. Прислать значения для `.env`/GitHub Variables: `SMTP_HOST`, `SMTP_USER`, `SMTP_FROM_EMAIL`
   и пароль приложения в секрет `SMTP_PASSWORD`.
