# 0003. Образы в GHCR и деплой на один VPS через Compose

- **Статус:** принято
- **Дата:** 2025-11-13

## Контекст

Проект разрабатывает один человек. Нужны воспроизводимые сборки, проверка того же артефакта,
который поедет на прод, и деплой без ручных шагов. Многоинстансовость не требуется
(см. AGENTS.md, «Допущения о развертывании»).

## Решение

- Образы `api` и `web` собираются в CI и публикуются в GHCR с тегом `sha` и `latest`.
- Рантайм на VPS — `docker-compose.prod.yml`: `db`, `api`, `web`; наружу сервисы не публикуются.
- Деплой — job в `release.yml` по SSH: scp compose и `.env`, затем `docker compose pull && up -d`.
- Образ API собирается с `pnpm deploy --prod`: в рантайм попадают только production-зависимости.
- Образ web — Next.js `output: 'standalone'`, бренд передаётся build-arg'ами (`NEXT_PUBLIC_*`).
- Деплой выключен по умолчанию: выполняется только при `DEPLOY_ENABLED=true`.

## Последствия

- Положительные: локально проверяется тот же образ, что в проде; откат — смена тега.
- Отрицательные: `NEXT_PUBLIC_*` фиксируются на этапе сборки — смена бренда требует нового образа.
- Запрещено: собирать образы на VPS, деплоить тегом `latest`, публиковать порты сервисов наружу.
