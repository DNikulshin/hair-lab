# 0003. Образы в GHCR и деплой на один VPS через Compose

- **Статус:** принято
- **Дата:** 2025-11-13

## Контекст

Проект разрабатывает один человек. Нужны воспроизводимые сборки, проверка того же артефакта,
который поедет на прод, и деплой без ручных шагов. Многоинстансовость не требуется
(см. AGENTS.md, «Допущения о развертывании»).

## Решение

- Образы `api` и `web` собираются в CI и публикуются в GHCR с тегом `sha` и `latest`.
- Рантайм на VPS — `docker-compose.prod.yml`: `db`, `api`, `web`; наружу сервисы не публикуются.
- Деплой — job в `release.yml` по SSH: scp compose и `.env`, затем `docker compose pull && up -d`.
- Миграции БД — отдельным образом (`apps/api/Dockerfile`, стадия `migrations`) из того же
  коммита и с тем же тегом, что api: в рантайм-образе api нет prisma CLI и миграций. На VPS —
  `docker compose run --rm migrations` между `pull` и `up -d`; падение миграции останавливает
  деплой, старые контейнеры продолжают работать.
- Образ API собирается с `pnpm deploy --prod`: в рантайм попадают только production-зависимости.
- Образ web — Next.js `output: 'standalone'`, бренд передаётся build-arg'ами (`NEXT_PUBLIC_*`).
- Деплой выключен по умолчанию: выполняется только при `DEPLOY_ENABLED=true`.

## Последствия

- Положительные: локально проверяется тот же образ, что в проде; откат — смена тега.
- Положительные: версия схемы не разъезжается с версией кода (один коммит — один набор образов),
  а новый контейнер api не запускается до успешных миграций.
- Отрицательные: `NEXT_PUBLIC_*` фиксируются на этапе сборки — смена бренда требует нового образа.
- Отрицательные: образ миграций несёт слой с devDependencies воркспейса и заметно тяжелее нужного;
  слим-вариант — отдельная задача.
- Отрицательные: откат схемы автоматически не выполняется; несовместимые изменения — только
  expand/contract и новая миграция. Упавшая миграция снимается штатно
  (`prisma migrate resolve --rolled-back <имя>` в контейнере образа `migrations`), затем
  идемпотентная правка миграции новым коммитом. Миграция целиком в транзакции по умолчанию
  не выполняется; явные `BEGIN;`/`COMMIT;` — требование к новым миграциям
  (см. `docs/deploy.md`, раздел 5).
- Запрещено: собирать образы на VPS, деплоить тегом `latest`, публиковать порты сервисов наружу.
