# Ресерч: чем искать, чем читать, как проверять

Внешний ресерч (документация библиотек, changelog'и, статьи, обсуждения) — вспомогательный
источник. Источник истины по проекту — код и `docs/` (см. `AGENTS.md`): внешняя статья не
отменяет ни контракт в `packages/contracts`, ни запись в ADR.

## Маршрут «задача → инструмент»

| Задача                                         | Инструмент                                      | Чем проверить результат                     |
| ---------------------------------------------- | ----------------------------------------------- | ------------------------------------------- |
| Внешний веб-поиск                              | `web_search` (или MCP `searxng_web_search`)     | открыть первоисточник, не цитировать снипет |
| Технический поиск (код, пакеты, SO, MDN, GH)   | то же + `categories: "it"`                      | версия библиотеки в `package.json`/lock     |
| Научные статьи                                 | то же + `categories: "science"`                 | arXiv/DOI, а не пересказ                    |
| Новости (релизы компаний, инциденты)           | то же + `categories: "news"` + `time_range`     | дата публикации                             |
| Чтение страницы целиком                        | `web_url_read` / `web_fetch_md`                 | заголовки и код-блоки на месте              |
| Точечное чтение раздела (экономия контекста)   | `web_url_read` + `section` / `readHeadings`     | —                                           |
| Версии и API библиотек                         | Context7: `web_docs_search` → `web_docs_fetch`  | сверка с `node_modules`/`package.json`      |
| Наши решения, ADR, оркестратор                 | `local-rag_query_documents` со `scope=<корень>` | открыть сам файл `docs/`                    |
| JS-страница, SPA, **localhost** (staging 3010) | `playwright` / `chrome-devtools`                | консоль и сеть страницы                     |
| GitHub: issues, PR, CI-логи                    | `gh` CLI (GitHub MCP не подключаем)             | `gh pr checks`, `gh run view`               |
| Проверка спорного утверждения                  | ≥2 независимых источника + первоисточник        | `source_check` для пассажей                 |

`web_search` и MCP `searxng_web_search` ходят в один и тот же локальный инстанс
(`~/.pi/agent/web-search.json`, `docs/environment.md`), поэтому разница только в форме ответа:
MCP умеет категории, `readHeadings`/`section` и диагностику движков.

## Правила

1. **Снипет — не источник.** Цитировать и принимать решение по первоисточнику: документация
   производителя, release notes, RFC, issue в upstream-репозитории.
2. **Проверять ссылку до цитирования.** В выдаче встречаются нерабочие обёртки вида
   `http:///go/v1/...` (хост не разрешается). Такую ссылку — выбросить и найти канонический URL.
3. **Читать предупреждения выдачи.** Строка `⚠️ Some search engines were unavailable` означает
   неполный результат: часть движков отвалилась (таймаут, CAPTCHA, `access denied`).
4. **Сверять версию.** «Latest» в статье может быть старее нашего `package.json`. Для Next.js,
   Prisma, Fastify и Next-плагинов — сверять major/minor и пункт «Upgrading».
5. **Фиксировать дату.** Для «как сейчас принято» ставить `time_range` и указывать дату источника;
   для API — дату версии документации.
6. **Один источник — гипотеза, два — факт.** Если источники расходятся, приводить оба и явно
   писать, какой не проверен.
7. **Персональные данные и секреты не уходят в поиск** (`.env*`, данные клиентов, телефоны).
8. **Чужой код не копировать** в проект без сверки с лицензией и с нашими правилами слоёв.

## Ограничения MCP-ресерча (проверено 2026-11-17)

- Закрытые и платные источники недоступны: авторизации нет.
- `web_url_read` **блокирует** приватные адреса (`127.0.0.1`, локальная сеть) — для staging и
  preprod только браузер (`playwright`/`chrome-devtools`) или `curl`.
- Часть сайтов не читается из-за TLS (`DEPTH_ZERO_SELF_SIGNED_CERT`) — тогда браузер.
- GitHub UI-страницы читаются шумно (навигация сайта впереди контента) — для GitHub `gh` CLI.
- Фильтр `engines` в `searxng_web_search` ненадёжен: категория фильтрует, конкретный движок — нет.
  Запрос с явным `engines` может и вовсе зависнуть до клиентского таймаута.
- Один локальный инстанс — точка отказа. Если он лежит, `web_search` уходит в резервный
  провайдер (`duckduckgo`), а MCP-инструменты SearXNG просто не отвечают.
- Выдача ограничена: 1–20 результатов на запрос (`num_results`).

## Диагностика

```bash
curl -s -G 'http://127.0.0.1:8888/search' \
  --data-urlencode 'q=test' --data-urlencode 'categories=it' \
  --data-urlencode 'format=json' | python3 -m json.tool | head -20
```

Ответ должен быть JSON с `results` и `unresponsive_engines`. Пустой `results` при живом контейнере —
повод смотреть `unresponsive_engines`. Перезапуск контейнера и правка настроек — в
`docs/environment.md` (Docker из snap: перезапуск делать в своём терминале, из pi он падает).

После правки `~/.pi/agent/mcp.json` нужен `/reload` в pi: серверы поднимаются с окружением,
прочитанным один раз на процесс.
