### 3.8 Граница `core` ↔ `evals` и зависимости между слоями

Решение принято здесь и на этап D не откладывается: **`scripts/lib/evals/cost.mjs` входит в
`core`** (вариант «а»).

Обоснование одной фразой: это чистые функции без `fs`, `node:`-модулей и сетевых вызовов, а
ядру он нужен для бюджетного порога §5.6 (`cycle-decide.mjs:81`), поэтому держать его в слое
замеров — значит получить зависимость `core → evals` при уже существующей `evals → core`.

Факт импорта: `scripts/lib/cycle/cost.mjs:13` — `import { priceStage, readPrices } from '../evals/cost.mjs'`
(плюс type-only ссылки на `ModelPrice` в `:134,:184`). Меняется только категория файла в этом
документе: путь остаётся `lib/evals/cost.mjs`, раскладка `lib/cycle/` + `lib/evals/`
сохраняется, поэтому `../evals/cost.mjs` разрешается и правок в коде не требуется.

Следствие для копирования: **`core`-набор = `scripts/cycle-*.mjs` кроме `cycle-usage.mjs`,
`scripts/lib/cycle/*.mjs` кроме `config.mjs` (он `project-config`), `scripts/lib/evals/cost.mjs`,
`scripts/fixtures/cycle/**` и их тесты**. Копировать `core` без `scripts/lib/evals/cost.mjs`
нельзя — импорт не разрешится; без `lib/cycle/config.mjs` — тоже (в dev-harness он станет
шаблоном `project-config`, но интерфейс `GATES`/`LIMITS` обязателен).

Кто кого требует (проверено grep'ом импортов):
