# Как показывать макеты и скриншоты владельцу

Задача: владелец смотрит результат со смартфона (Pi Web), макеты живут на dev-хосте.
Прямые пути не работают, поэтому в проекте принят свой механизм — он ниже. Рабочий процесс
описан в скилле `.pi/skills/design-preview/SKILL.md`, здесь — «почему так» и чем это
обслуживается.

## Почему «просто открыть ссылку на localhost» не вариант

| Препятствие                                | Факт                                                                                                                               |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `127.0.0.1` для телефона — это сам телефон | dev-хост доступен только по LAN/через прокси                                                                                       |
| Ad-hoc порты закрыты                       | `ufw` включён, `DEFAULT_INPUT_POLICY=DROP`; docker CLI у `dev` нет, чтобы обойти                                                   |
| `nginx` не прочитает каталог агента        | `/home/dev` = `750`, `~/.pi` = `700`, `www-data` не пройдёт                                                                        |
| Наружу открыт не 443                       | проброшен **8443 → внутренний 443** (`docs/deploy.md`)                                                                             |
| Google Fonts недоступен                    | `ERR_CONNECTION_RESET`, поэтому шрифты вендорятся в `apps/web`                                                                     |
| Публичные туннели не годятся               | `cloudflared --tunnel quick` регистрируется, но край отдаёт `502/530` (`datagram manager error: timeout`) — QUIC/UDP режется сетью |

## Три канала, по возрастанию сложности

1. **Картинка прямо в чат (основной).** `chrome-devtools` MCP, `take_screenshot` **без `filePath`**:
   скриншот возвращается image-content, Pi Web рисует его в транскрипте с лайтбоксом
   (`appendImage` для `toolResult` в `public/app.js` пакета `pi-package-webui`). Вложения `read`
   так не отображаются — только как файл для агента.
2. **Files panel в Pi Web.** `/api/files` показывает и gitignored-пути (`.pi/artifacts/**`),
   у PNG `canOpenInWebui: true`. HTML открывается как текст (`kind: "text"`) — не рендерится,
   поэтому визуальная оценка идёт по PNG, а интерактивная — по ссылке (канал 3).
3. **Ссылка для другого устройства.** Файлы публикуются в `/srv/preview`, раздаёт тот же nginx:
   `https://pi.dnikulshin.ru:8443/preview/<slug>/`. TLS и basic-auth наследуются от server-блока
   `pi.dnikulshin.ru`, новых портов и правил `ufw` не требуется; работает и с мобильного интернета.

## Обслуживание канала 3 (host-level, вне репозитория)

Инструменты живут в домашнем каталоге агента, потому что это не продуктовый код и не должно
попадать в PWA-сборку:

| Файл                                      | Роль                                                                                                                                                                                                                                                                       |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `~/.pi/agent/bin/preview-publish.mjs`     | публикация каталога: копирует (не симлинк — nginx не пройдёт сквозь `750`), `chmod a+rX`, транслитерация slug, `--list`, `--remove`, всегда JSON-ответ. `PREVIEW_ROOT` (по умолчанию `/srv/preview`), `PUBLIC_BASE` (по умолчанию `https://pi.dnikulshin.ru:8443/preview`) |
| `~/.pi/agent/extensions/preview-share.ts` | тул `publish_preview` и команда `/share <dir> [slug]` / `/share list` / `/share remove <slug>`                                                                                                                                                                             |
| `~/.pi/agent/bin/preview-nginx-setup.sh`  | разовая настройка с root: `install -d /srv/preview` (владелец `dev`, группа `www-data`, 2750, setgid) → сниппет `/etc/nginx/snippets/preview.conf` → `include` в server-блок `pi.dnikulshin.ru` (бэкап `dev.conf.bak-<дата>`) → `nginx -t` → `reload`. Идемпотентно        |

Однократный запуск (абсолютный путь: `~` у sudo будет свой, а `~/.pi` доступен только `dev` и root):

```bash
sudo /home/dev/.pi/agent/bin/preview-nginx-setup.sh
```

Проверка маршрута изнутри хоста (снаружи нельзя: hairpin-NAT на роутере не работает):

```bash
curl -sk --resolve pi.dnikulshin.ru:443:127.0.0.1 https://pi.dnikulshin.ru/preview/   # → 401 (auth)
curl -s  --resolve pi.dnikulshin.ru:443:127.0.0.1 http://127.0.0.1/preview/           # → 000
```

Публикация и уборка:

```bash
node ~/.pi/agent/bin/preview-publish.mjs .pi/artifacts/<каталог>   # → {"ok":true,"url":…}
node ~/.pi/agent/bin/preview-publish.mjs --list
node ~/.pi/agent/bin/preview-publish.mjs --remove <slug>
```

Откат: убрать строку `include snippets/preview.conf;` из `/etc/nginx/conf.d/dev.conf`
(или вернуть бэкап) и `systemctl reload nginx`.

## Правила

- В `/srv/preview` не публикуем ничего с персональными данными, `.env*` и приватными экранами
  кабинета — это статические макеты и скриншоты витрины.
- Макеты остаются в `.pi/artifacts/` (в git не попадают). В репозиторий кладём только то,
  что нужно сохранить: принятую дизайн-систему и архив отклонённых направлений — они живут
  в `docs/design/` (см. ветку `design/13-razmetka` / PR #118).
- Долговременная ссылка на макеты не нужна: канал 1 показывает картинку сразу, канал 3 —
  для «потыкать» конкретную итерацию.
