# Внешние интеграции

Все секреты — только в окружении (`.env` на VPS, GitHub Secrets для CI). В репозиторий,
issues и тесты попадают лишь вымышленные значения. В коде секреты читаются один раз
при старте и валидируются Zod.

## ЮKassa (оплата записи)

Решение: полная оплата записи онлайн. На этапе разработки используется **тестовый магазин**
ЮKassa — он позволяет пройти весь сценарий без реальных списаний.

Планируемые переменные окружения API:

| Переменная            | Назначение                                              |
| --------------------- | ------------------------------------------------------- |
| `YOOKASSA_SHOP_ID`    | идентификатор магазина                                  |
| `YOOKASSA_SECRET_KEY` | секретный ключ (только в `.env`/секретах)               |
| `YOOKASSA_RETURN_URL` | возврат клиента после оплаты                            |
| `PAYMENTS_MODE`       | `test` или `live` — защита от случайных боевых платежей |

Принципы:

- сумма и назначение платежа определяются на сервере, не приходят от клиента;
- вебхук проверяет подлинность и обрабатывается идемпотентно (повтор не меняет состояние);
- запись подтверждается только после успешной оплаты; истёкшая оплата освобождает слот;
- секретный ключ не логируется, тела вебхуков логируются без персональных данных.

## Email

Канал: SMTP. Провайдер выбирается владельцем на этапе подключения:

- **Яндекс 360** — `smtp.yandex.ru:465` (SSL), логин — адрес ящика, пароль — пароль приложения;
- **Google Workspace** — `smtp.gmail.com:465` (SSL), пароль приложения; для личного Gmail
  нужен «пароль приложения» при включённой двухфакторной аутентификации.

Переменные:

| Переменная        | Тип             | Значение                               |
| ----------------- | --------------- | -------------------------------------- |
| `SMTP_HOST`       | GitHub Variable | `smtp.yandex.ru` или `smtp.gmail.com`  |
| `SMTP_PORT`       | GitHub Variable | `465` (SSL)                            |
| `SMTP_SECURE`     | GitHub Variable | `true`                                 |
| `SMTP_USER`       | GitHub Variable | полный адрес ящика                     |
| `SMTP_PASSWORD`   | GitHub Secret   | пароль приложения                      |
| `SMTP_FROM_EMAIL` | GitHub Variable | адрес отправителя (домен салона)       |
| `SMTP_FROM_NAME`  | GitHub Variable | отображаемое имя, например «Стриж Lab» |

Адрес отправителя должен совпадать с доменом салона, иначе письма попадают в спам.
Яндекс 360 требует подтверждения домена, Google — включённой двухфакторной аутентификации
и пароля приложения.

## Аутентификация (issue #6)

| Переменная    | Тип             | Значение                                                  |
| ------------- | --------------- | --------------------------------------------------------- |
| `AUTH_SECRET` | GitHub Secret   | случайная строка ≥ 32 символов: `openssl rand -base64 48` |
| `APP_URL`     | GitHub Variable | `https://<домен>` — база для ссылок входа и подтверждений |

Валидация при старте: обязательные переменные проверяются всегда, интеграционные —
только когда интеграция включена (`PAYMENTS_MODE`, заполненный `SMTP_HOST`). Пока значения
пустые, API работает без соответствующих модулей.

Принципы:

- отправка вне транзакции записи: outbox + воркер с ретраями (сбой почты не ломает запись);
- письма содержат минимум данных: имя, услуга, дата/время, ссылка;
- ссылки входа одноразовые и короткоживущие.

## nginx на хосте

Единственная точка входа. Контейнеры опубликованы только на loopback:

- `127.0.0.1:3000` — web;
- `127.0.0.1:3001` — api, снаружи доступен как `/api/*` (префикс отрезается).

Конфиг: `deploy/nginx/hair-lab.conf.example` (TLS, заголовки безопасности, gzip, кэш статики).
Сертификаты — Let's Encrypt (certbot) или уже имеющиеся.

Проверка после настройки: `https://<домен>/` открывается, `https://<домен>/api/health` отдаёт
`{"status":"ok",...}`, а `curl http://127.0.0.1:3001/health` снаружи недоступен.
