# MCP: что подключено, когда брать, что делать без него

Агент работает в сессии с MCP-серверами (`pi`), но не зависит от них: у каждого сервера есть
замена на shell/файлы/API. Этот файл — реестр и правило обращения. Маршрутизация внешнего
ресерча — `docs/research.md`, браузерная проверка web-правок — `docs/qa-web.md`.

## Правило обращения

1. **Бери MCP, когда он точнее или дешевле shell.** Признаки: вместо догадок — факт
   (SQL к dev-БД), вместо `curl` + парсинга — браузер, вместо ручного `grep` по сорока файлам —
   поиск по индексу `docs/`.
2. **Остальное — обычными инструментами.** Код, `git`, `gh`, файлы, запуск тестов и сборок MCP
   не заменяет; дублировать ими `gh` или `git` не нужно.
3. **MCP недоступен — не блокируйся.** Возьми fallback из таблицы ниже, выполни задачу и явно
   напиши, что сработал fallback и почему (сервер не поднялся, нет Docker, ошибка соединения).
   Молча деградировать нельзя: результат без пометки выглядит как проверенный MCP.
4. **Нужен прирост — предложи настроить.** Если без MCP задача становится заметно дороже
   (много ручной работы, слепые места в проверке), сформулируй владельцу: какой сервер, что он
   даст, что нужно для запуска (Docker/бинарь, токен, права, зависимости), какие риски.
   Решение принимает владелец; сам агент MCP не устанавливает и не включает.
5. **Секреты и персональные данные не уходят в MCP-вызовы** так же, как и в shell: `.env*`,
   данные клиентов, телефоны — не отправлять. Токены — только через окружение
   (`${VAR}`) или `!command` в конфиге, не литералом.

## Реестр

| Сервер            | Что даёт                                                             | Fallback                                                             |
| ----------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `local-rag`       | поиск по `docs/` (hybrid), синхронизация индекса, соседние чанки     | `grep`/`find_files`/чтение файлов `docs/` напрямую                   |
| `postgres`        | read-only SQL к dev-БД `127.0.0.1:55432/hair_lab` (один `query`)     | `docker exec hair-lab-dev-db-1 psql -U hair_lab -c '<sql>'`          |
| `searxng`         | веб-поиск по категориям, чтение URL по разделам, диагностика движков | `web_search` (тот же инстанс), `web_fetch_md`, `curl`                |
| `playwright`      | браузер: JS-страницы, localhost, скриншоты, консоль, сеть            | `chrome-devtools`, `curl` + `grep` по HTML, `curl -I` для заголовков |
| `chrome-devtools` | то же плюс performance-трейсы, lighthouse, heap-снапшоты             | `playwright`, `node --cpu-prof`, `pnpm build` с профилем             |
| `mcp` (gateway)   | установка/статус MCP-серверов по URL                                 | `pi mcp list`, `pi mcp add`, `/mcp`                                  |

Не подключаем: **GitHub MCP** — remote-эндпоинт требует Copilot-энтайтлмент (проверка 2026-11-17:
`403 forbidden`), локальный дублирует `gh` и отдаёт ответы в 80 раз более многословные.

## Здоровье и настройка

```bash
pi mcp list          # состояние, число инструментов, источник конфигурации
/mcp                 # в сессии: инструменты, sign-in, reconnect, exposure
/mcp reconnect searxng
/reload              # после правки конфигов вне сессии
```

- Конфиги: `~/.pi/agent/mcp.json` (личные, с секретами), `.pi/mcp.json` (проектные, только нужное
  проекту; читается после доверия проекту).
- Логи: `~/.pi/agent/mcp.log` (пишутся серверные уведомления и ошибки соединения).
- Экспозиция по умолчанию — `codemode`: инструменты не объявляются в промпте и не жгут контекст,
  вызываются через шлюз. `direct` — только для маленьких и часто нужных наборов.
- Новый сервер: `pi mcp add <name> -- <command>` или `pi mcp add <name> --url <url>`; после —
  `pi mcp list` для проверки, затем предложить владельцу оценить пользу до включения в работу.

## Если MCP нет вовсе

Сессия без MCP-серверов — рабочее состояние, а не авария: код, тесты, `git`, `gh`, `curl`,
`docker` и файлы остаются. Что при этом теряется:

| Без сервера  | Что дороже вручную                                                      |
| ------------ | ----------------------------------------------------------------------- |
| `local-rag`  | навигация по `docs/` — дольше, но выполнимо `grep`/`read`               |
| `postgres`   | инспекция схемы: `docker exec … psql` или чтение `prisma/schema.prisma` |
| `searxng`    | внешний ресерч: остаётся `duckduckgo` через `web_search`                |
| `playwright` | проверка UI: `curl` видит только HTML без JS и консоли                  |

Если пункт из правой колонки — ключ к задаче (например, браузерная проверка web-правки),
это повод предложить владельцу поднять сервер, а не подменять проверку догадкой.
